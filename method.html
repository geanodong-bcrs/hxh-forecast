How this works
and where it is weakest

The question

Hunter × Hunter has not been a weekly series since 2006. It comes out in runs of about ten chapters, separated by breaks that have ranged from nothing at all to three and a half years. Within a run, chapters appear one per week almost without exception — 143 of the last 145 gaps were exactly one issue.

So there is really only one hard question: when does the next run start? Everything else follows from it, which is why the ten-chapter tables are so tightly bunched.

The three levels

0 — already announced

If Shueisha has named the issue, there is nothing to predict. That chapter is recorded as scheduled and drops out of the model.

0 — issues ruled out

Issues publicly reported not to carry the series are removed from the candidate set. This is a factual exclusion, not evidence about Togashi’s pace — nothing else in the model changes.

If they turn out to be wrong the row is deleted and the forecast returns — the snapshot for every run in between stays on the record either way.

1 — what history alone suggests

Built from publication records only, never from Togashi’s posts — otherwise the next step would not be an update. There are 16 gaps between runs since 2007, and they are bimodal: three times the next run began with no wait at all, the rest after waits of 9 to 184 issues. A single smooth curve would describe neither case, so the model uses a mixture. See the full statistical-methods paper and its plot →

That mixture, drawn. The tick marks along the bottom are the 16 observations the whole prior is built from, at the weight each carries — the three zeros count as two, because two of them are the same run continuing rather than two separate decisions to carry straight on. The bar at gap 0 is clipped: it is about twenty times the height of the curve, and drawing it to scale would flatten everything else to nothing. The curve itself is close to flat from 1 to 100 — with a 60-issue kernel over sixteen points, the prior says little about how long a wait will be once there is a wait at all.

2 — what Togashi’s posts add

Production data covers only 3 past runs. That is far too few to fit a curve to, but enough to compare the current batch’s chapter-readiness states with what was publicly reported before each past run began. The model asks: if this batch behaves like that one, when would it start?

Putting them together

The current run has readiness evidence for 10 chapters. Those are not 10 independent pieces of evidence — they are one person’s working process observed across a batch. Treating every tweet as independent would produce a forecast about a week wide: very impressive, and wrong. So each past run counts once, and the confidence scales with how many comparable runs exist, not how many posts there are.

How production evidence is used

The run is at 8.70 of 10.00 ordered chapter-equivalents. At that same readiness, the three resolved production-era runs imply start dates of 2026-09-13, 2026-12-03, 2027-02-08. Each supplies one broad 120-day component; the components are averaged, not multiplied. This makes dates far beyond every comparable readiness trajectory less likely while preserving a wide tail for Shueisha’s independent scheduling decision.

How continued non-publication is handled

Each forecast rules out issues already known not to contain the batch. This is a factual update, applied continuously. It can gradually move the forecast later during a hiatus, but does not treat silence as a new production milestone.

The forecast history, and which of it is reconstructed

180 of 190 points were re-run afterwards

The model started producing forecasts on 2 Sep 2026, but the interesting stretch is the whole of the run that produced the evidence it uses. So it was replayed: for each earlier date it was re-run seeing only the chapters published, the issues on sale and the production posts made by that date. Those points are marked provenance: replay in the stored snapshot and the charts rule off where the live record begins.

One honest caveat. An event enters the replay on the day it happened, not the day it was known — some readings come from images transcribed and human-checked later, and some posts were only found through the Wayback Machine. The replay is therefore very slightly better informed than a live run would have been. The batch’s length is treated the same way throughout, as an assumption rather than as evidence that arrived on some date.

Where it is weakest

The headline number is the least defensible part

The 2.8% on 1 Jan 27 comes from a point mass estimated from two clustered observations from 2010–2012. It says there is roughly an even chance the series rolls straight from this run into the next with no break — which has not actually happened since 2012. It survived every check I ran, and it is still the claim I would least want to defend.

  1. The production side has never been scored against a real outcome. Three comparable runs, and none has started since the method was built. Chapter 421 will be the first genuine test.
  2. No accuracy figures are published. Scoring honestly means separating forecasts made before an official announcement from those made after, and that record has not been built yet. Without the split the numbers would measure how early Shueisha announces things, not whether this model knows anything. They are left out rather than estimated.
  3. Silence is deliberately mostly neutral. The forecast holds between public production or publication updates. That avoids arbitrary date drift, but it also means an ordinary long silence contributes little information until it becomes a record hiatus.
  4. Chapters 431–440 rest on history alone. The only production events reported for them are at the earliest stage, which says nothing about scheduling.
  5. Where this run ends is assumed, not confirmed. A post from April 2026 can be read as “chapter 420 onward”, which would shift everything by ten chapters.
  6. Both publication sources are secondary. Nothing has been checked against Shueisha directly.
